## WebGL 2 移植

| 阶段 | 数据 / 操作 |
| --- | --- |
| 表面绑定 | 局部 / 表面 UV |
| 屏幕足迹 | `dFdx`、`dFdy` |
| 频率 | UV Jacobian 的最大、最小奇异值 |
| 分形层级 | `floor(log2(spacing))` |
| 图案 | `64 × 64 × 16` R8 3D 纹理 |
| 亮度校准 | 原作者 brightness ramp |
| 层间变化 | 嵌套 Bayer 点集，新增 / 移除点 |
| 阈值 | 亮度、对比度、点径变化、拉伸补偿 |
| 比较模式 | 屏幕 Bayer / 固定表面纹理 |

核心移植保留了原作者的灰阶算法、亮度间距补偿、层级量化、反相点阵和径向补偿。3D 纹理在离线打包时从上游 PNG 栈解码，显式恢复 Unity 的自下而上切片和行顺序；浏览器直接读取 R8 二进制数据。展示场景和相机交互为本项目代码；没有移植原视频中的游戏场景，也未实现上游的 RGB、CMYK 和天空盒功能。

## 6 秒几何体预设

入口：`/techniques/surface-dither.html?preset=reference`。普通入口保留旧墙面场景，可在预设中切换。

- 参考：额外检查了公开预览 4–9 秒，目标为约 6 秒的球体、立方体细点阵。
- 构图：两个球体、三个方块、有限平面；前景方块遮挡大球。几何位置、相机与光照为依据画面重建的近似值。
- 画布：默认按 CSS 尺寸 × DPR 设置输出缓冲区；可选固定 720 × 480、960 × 540、1920 × 1080；相机 FOV 60°；scale 5.9；默认静止。
- 分辨率：补上原作者 `Dither3DGlobalProperties.cs` 中的 `scale + log2(height / referenceHeight)`，基准高度 1080。此前直接把作者尺度用于 480 高画布，点阵过粗；算法测试通过不能证明与参考画面相符。
- 采样：64 × 64 × 16 的上传字节与原作者 Unity 纹理数据完全相同（65536 字节，SHA256 `671715318fdac01cfbf9e353f4418e39c6feee4f42499b8eb8986f3f2a6178ca`）。
- 上一版固定画布、单样本的局部比较（历史测量，不作为本版抗混叠证据）：原预览 978 × 550 的方块正面 ROI `(245,137)–(330,200)`，本实现原生 960 × 540 ROI `(350,105)–(425,170)`。RGB 最小通道 ≥180，四连通域排除边界与面积 ≤1、≥100 的区域，白点面积中位数均为 5 px²；样本数分别为 33、53。该数值只校准局部点径，不代表构图、亮度或整幅图已完全一致。

验证平面：相机 yaw=0、pitch=0、FOV=45°，曝光=0.55，scale=7，基准高度480，径向补偿关闭，视口720×480。中央300×200区域统计不接触边界、面积2–999像素、红通道≥140的白色连通域。自动测试要求距离10与4的分形点面积中位数比值为0.75–1.3，固定表面模式近处与远处的比值大于3.3；该测试仅验证尺寸保持。浏览器测试另外检查预设切换、画布比例、分辨率校正与参数重置。


限制：斜视方向会压缩点，球面 UV 存在极点畸变，几何边缘的导数会产生局部差异。这里的“分形”是点阵层级的自相似关系，与 Mandelbrot 集绘图不是同一个目录条目。

## 显示与采样

此前固定 960 × 540 的画布在约 851 CSS 像素宽的窗口中通过 `image-rendering: pixelated` 再次采样，未匹配设备 DPR；这会引入额外的空间混叠。现默认自动匹配设备像素，并改用 `image-rendering: auto`；全屏时重新计算输出尺寸。固定分辨率选项用于直接比较，缩放显示时仍可能出现重采样纹路。

参考预设默认 2 × 2 超采样：先在双倍宽高的 RGBA8 缓冲区完成场景与抖动计算，再用 `texelFetch` 对四个样本等权平均，输出到原生尺寸画布。层级与对比度使用内部采样高度进行分辨率归一化，保持最终点阵尺度。采样缓冲区超过设备纹理尺寸或 16777216 像素时，改为四次带 ±0.25 像素偏移的渲染，以加法混合累计四分之一颜色；仍保留 2 × 2 采样。UV 导数和尺度按虚拟双倍采样高度校正。旧预设仍默认 1 × 1。

自动测试检查 DPR=2、窗口调整、全屏后的输出尺寸，GPU 四样本平均结果，以及切换采样时点径保持。它们验证采样链路，不证明完全消除摩尔纹；斜视压缩、球面 UV、点阵本身的周期结构与浏览器后续缩放仍需区别判断。

## Firefox 隐私模式与纹理加载

用户日志：Firefox 158 / Windows，DPR=2，画布1530×861，distance=3，yaw=2.784，pitch=0.07，请求2×2但实际1×1。该像素数未超过采样预算，纹理尺寸限制是需要检查的条件。

在 Firefox 142 / Mesa 中开启 `privacy.resistFingerprinting` 后复现：`MAX_TEXTURE_SIZE` 从16384变为2048，旧加载器通过 `CanvasRenderingContext2D.getImageData` 读取的 PNG 像素也发生改变，画面出现大面积弯曲条纹。旧图案数据的 SHA256 不再等于上游值。此前的摩尔纹判断和额外灰阶过滤没有定位这个原因，已移除该过滤；保留稳定的 SVD 最小奇异值计算、原作者拉伸补偿及超采样。

| 路径 | 原始纹理校验 | 最大纹理尺寸 | 实际采样 |
| --- | --- | --- | --- |
| 旧 PNG / 普通 Firefox | 符合 | 16384 | 2×2 |
| 旧 PNG / 抗指纹模式 | 不符合，复现条纹 | 2048 | 1×1 |
| 原始二进制 / 抗指纹模式 | 符合 | 2048 | 2×2，四次累计 |

浏览器现在只用 `fetch` 和 `arrayBuffer` 加载 `pattern.bin`、`ramp.bin`，不使用 Canvas 像素提取。图案仍是原来的65536字节，SHA256 `671715318fdac01cfbf9e353f4418e39c6feee4f42499b8eb8986f3f2a6178ca`；亮度查找表为64字节，SHA256 `e9d18b616b1062ea7b0ae19a8f842980beb2acfca3e0de8308144265a08850c5`。离线重建命令：`python tools/pack-dither.py`，只在重建数据时需要 Pillow，正常 npm 构建无需 Python。

回归测试覆盖禁止 Canvas 提取时仍能初始化、原始数据校验、模拟2048尺寸限制时累计采样与大缓冲采样的像素差异，以及实际 Firefox 抗指纹模式下用户的1530×861低视角配置。RFP 模式下不把 WebGL 像素读回值当作可靠图像依据，使用原始字节校验、渲染状态与浏览器截图。截图检查已确认条纹消失、点阵恢复；Windows / Firefox158的实际显卡仍未直接运行。

页面“复制参数”包含配置、画布尺寸、DPR、实际采样、采样路径、纹理尺寸上限和浏览器名称，不发送遥测。Firefox 回归：`npx playwright install --with-deps firefox`，然后在有 X 显示的 Linux 中运行 `LIBGL_ALWAYS_SOFTWARE=1 npm run test:firefox`；CI 用 `xvfb-run -a npm run test:firefox` 创建显示环境，每次部署检查普通模式与抗指纹模式。

## 输出灰阶

默认亮部上限为0.78（约199/255），背景灰度为0.66（约168/255）。这两个参数在抖动计算后映射输出颜色，调低屏幕亮部而不改变点阵分布；曝光与亮度偏移仍用于控制输入明暗。参考几何体场景把两项设为1可恢复原来的纯白输出。
