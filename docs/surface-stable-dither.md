## WebGL 2 移植

| 阶段 | 数据 / 操作 |
| --- | --- |
| 表面绑定 | 局部 / 表面 UV |
| 屏幕足迹 | `dFdx`、`dFdy` |
| 频率 | UV Jacobian 的最大、最小奇异值 |
| 分形层级 | `floor(log2(spacing))` |
| 图案 | `64 × 64 × 16` R8 3D 纹理 |
| 亮度校准 | 原作者 brightness ramp |
| 层间变化 | 嵌套 Bayer 点集，新增 / 移除点 |
| 阈值 | 亮度、对比度、点径变化、拉伸补偿 |
| 比较模式 | 屏幕 Bayer / 固定表面纹理 |

核心移植保留了原作者的灰阶算法、亮度间距补偿、层级量化、反相点阵和径向补偿。3D 纹理从上游 PNG 栈解码，显式恢复 Unity 的自下而上切片和行顺序。展示场景和相机交互为本项目代码；没有移植原视频中的游戏场景，也未实现上游的 RGB、CMYK 和天空盒功能。

## 6 秒几何体预设

入口：`/techniques/surface-dither.html?preset=reference`。普通入口保留旧墙面场景，可在预设中切换。

- 参考：额外检查了公开预览 4–9 秒，目标为约 6 秒的球体、立方体细点阵。
- 构图：两个球体、三个方块、有限平面；前景方块遮挡大球。几何位置、相机与光照为依据画面重建的近似值。
- 画布：默认按 CSS 尺寸 × DPR 设置输出缓冲区；可选固定 720 × 480、960 × 540、1920 × 1080；相机 FOV 60°；scale 5.9；默认静止。
- 分辨率：补上原作者 `Dither3DGlobalProperties.cs` 中的 `scale + log2(height / referenceHeight)`，基准高度 1080。此前直接把作者尺度用于 480 高画布，点阵过粗；算法测试通过不能证明与参考画面相符。
- 采样：64 × 64 × 16 的上传字节与原作者 Unity 纹理数据完全相同（65536 字节，SHA256 `671715318fdac01cfbf9e353f4418e39c6feee4f42499b8eb8986f3f2a6178ca`）。
- 上一版固定画布、单样本的局部比较（历史测量，不作为本版抗混叠证据）：原预览 978 × 550 的方块正面 ROI `(245,137)–(330,200)`，本实现原生 960 × 540 ROI `(350,105)–(425,170)`。RGB 最小通道 ≥180，四连通域排除边界与面积 ≤1、≥100 的区域，白点面积中位数均为 5 px²；样本数分别为 33、53。该数值只校准局部点径，不代表构图、亮度或整幅图已完全一致。

验证平面：相机 yaw=0、pitch=0、FOV=45°，曝光=0.55，scale=7，基准高度480，径向补偿关闭，视口720×480。中央300×200区域统计不接触边界、面积2–999像素、红通道≥140的白色连通域。自动测试要求距离10与4的分形点面积中位数比值为0.75–1.3，固定表面模式近处与远处的比值大于3.3；该测试仅验证尺寸保持。浏览器测试另外检查预设切换、画布比例、分辨率校正与参数重置。


限制：斜视方向会压缩点，球面 UV 存在极点畸变，几何边缘的导数会产生局部差异。这里的“分形”是点阵层级的自相似关系，与 Mandelbrot 集绘图不是同一个目录条目。

## 显示与采样

此前固定 960 × 540 的画布在约 851 CSS 像素宽的窗口中通过 `image-rendering: pixelated` 再次采样，未匹配设备 DPR；这会引入额外的空间混叠。现默认自动匹配设备像素，并改用 `image-rendering: auto`；全屏时重新计算输出尺寸。固定分辨率选项用于直接比较，缩放显示时仍可能出现重采样纹路。

参考预设默认 2 × 2 超采样：先在双倍宽高的 RGBA8 缓冲区完成场景与抖动计算，再用 `texelFetch` 对四个样本等权平均，输出到原生尺寸画布。层级与对比度使用内部采样高度进行分辨率归一化，保持最终点阵尺度。采样缓冲区超过设备纹理尺寸或 16777216 像素时降为 1 × 1，参数栏显示实际采样值。旧预设仍默认 1 × 1。

自动测试检查 DPR=2、窗口调整、全屏后的输出尺寸，GPU 四样本平均结果，以及切换采样时点径保持。它们验证采样链路，不证明完全消除摩尔纹；斜视压缩、球面 UV、点阵本身的周期结构与浏览器后续缩放仍需区别判断。

## 欠采样条纹

参数扫描可复现周期条纹，尤其是点径变化=1、尺度=5、对比度=3、拉伸补偿=0的细点阵。仅在 Chromium 软件渲染器验证了这一复现；用户截图的完整参数、浏览器和硬件仍未知，尚不能确认该截图的唯一成因。用 `framebufferTextureLayer` 逐层读取当前 Chromium GPU 的 R8 纹理，65536 个红通道字节与上传数据逐字节一致，差异0，GL错误0；仅排除当前环境的纹理上传损坏。Firefox 已安装用于检查，但此执行环境的无头 Firefox 无法创建 WebGL 2 上下文，未把它记为通过。

新增最终显示频率过滤：以最大 UV 奇异值、分形层级、有效点数估计压缩方向的周期频率，换算到最终设备像素；在0.25–0.5周期/像素之间淡出到输入明暗，避免不可分辨周期形成干涉纹。该补充比上游原始实现更保守，斜视和高密度区域会变成灰阶。不能以消失的条纹代替与原视频一致性的证据。固定高分辨率画布缩小显示时也计入缩小倍率。固定表面对照模式采用相同频率限制；Bayer 对照模式限制为至少一个内部采样像素。

用 `abs(det) / sigmaMax` 求最小奇异值，避免极端斜视时相减丢失精度。回归测试在恒定明暗平面上复现未过滤的周期方差，再检查过滤后收敛到平均明暗；原有可分辨点径保持测试继续保留。页面“复制参数”包含配置、画布尺寸、DPR、实际采样和浏览器名称，供跨浏览器定位，不发送任何遥测。
